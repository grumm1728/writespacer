# Domain docs

WriteSpacer uses a single-context domain-document layout.

Before exploring or changing the codebase:

- Read the root `CONTEXT.md`.
- Read relevant decisions under `docs/adr/`.
- Use the glossary’s preferred terminology in tests, issues, plans, and code.
- If proposed work contradicts an accepted ADR, surface the conflict explicitly.
- If a referenced domain document does not exist, proceed silently.

The root `CONTEXT.md` contains the ubiquitous language. Repository-wide architectural decisions live under `docs/adr/`.
